# ADOFAI_Auto
The "A Dance of Fire and Ice" Auto Player (Frame sync Keyboard Recorder)

# 얼불춤의 오토플레이 구현

### 서문
이전에 얼불춤 오토를 개발하려 시도했지만,<br/>
시간을 저장하는 방법을 사용하여 게임과의 오차가 매우커져 실패했던 적이 있습니다.<br/>
하지만 리버스 엔지니어링 기술을 살짝 배우고,<br/>
이 영상을 보고 영감을 받아 다시 만들게 되었습니다.<br/>
영상 링크: https://youtu.be/xKgN097y-0A

### 기본 동작원리 (키보드 입력 녹화)

1. 얼불춤 프로세스에 일정하고 빠르게 상승하는 값의 주소를 찾습니다. (프레임(Frame) 이라고 하겠습니다)<br/>
  1-1. 테스트 결과 충분히 빠르게 상승하는 값이 아니면, 오차가 매우 커져 비정상 동작합니다.<br/>

2. 글로벌 버튼 입력(모든 키 입력)을 후킹합니다. (다른프로세스의 키입력도 받을 수 있게 됩니다)<br/>

3. 얼불춤의 키입력타이밍을 바탕으로 1번에서 찾은 프레임을 이용하여 타일간의 딜레이를 계산하여 저장합니다.<br/>

4. 3번의 과정을 레벨이 끝날때 까지 반복, 모든 타일의 딜레이를 저장합니다.<br/>

5. 4번에서 저장한 프레임 딜레이를 해당타일에서 딜레이만큼 기다리고 가상 키입력을 얼불춤 프로세스에 넣습니다.<br/>

6. 레벨이 자동으로 클리어 됩니다.<br/>

요약, 키보드 누르는 타이밍을 저장해서 그대로 출력함<br/>

### 추가 기능 구현 (딜레이 저장 및 수정기능)<br/>

만약 위 기본 동작에서 만들어진 딜레이 값을 저장 후 수정이 가능하다면<br/>
이론상 해당 스테이지는 완벽한 플레이가 가능하게 됩니다.<br/>

### 최신 버전 호환 (v2 변경점)
원본은 `UnityPlayer.dll+0x017EEDD0` 같은 **고정 포인터 경로**로 프레임 값을 읽어서, 게임이 업데이트될 때마다 주소가 어긋나 동작하지 않았습니다.<br/>
이제는 주소를 외우지 않고 **실행 중에 프레임 카운터를 직접 찾습니다.** (치트엔진의 "증가한 값 반복 스캔"을 자동화)

1. 짧은 간격으로 메모리를 두 번 읽어 "증가한 int" 후보를 모읍니다.
2. 여러 라운드 동안 계속 증가하는지 걸러냅니다.
3. 고속 샘플링으로 "변할 때마다 정확히 +1, 초당 20~600회" 인 값(프레임 카운터)만 남깁니다. (ms 타이머 등은 제외)
4. DLL 안의 정적 주소면 `frame_counter.cache` 에 저장해 다음 실행부터는 바로 사용합니다. 게임 실행 파일이 바뀌면(업데이트) 자동으로 다시 탐색합니다.

* 첫 탐색은 게임이 **화면에 표시된 상태**에서 수 초 걸립니다. 못 찾으면 게임 창을 띄운 채 `F5`.
* 일시정지 여부 / 입력 오프셋은 자동 탐색이 불가능하므로 `adofai_auto.ini` 에 포인터를 직접 적었을 때만 활성화됩니다. (없어도 녹화/재생은 정상 동작)
* 앱은 **x64** 로 빌드되며, 게임에 접근하지 못하면 관리자 권한으로 실행하세요.

### 최신 ADOFAI 구조 메모 (2026년 11월 기준 조사)
* 게임은 Mono 기반 Unity 게임이라 로직이 `<게임>_Data/Managed/Assembly-CSharp.dll` 에 들어 있습니다. 업데이트 때 exe는 그대로인 경우가 많아서, 캐시 키를 exe + `UnityPlayer.dll` + `Assembly-CSharp.dll` 의 크기/수정 시각으로 잡았습니다. (게임 버전은 UI에 표시)
* 모드 생태계는 Unity Mod Manager / BepInEx + Harmony 이고, 현재 PC 빌드는 3.4.x 대로 보입니다. 이 프로젝트는 모드 주입 없이 외부에서 메모리를 읽으므로 게임 내부 클래스명이 바뀌어도 영향이 없습니다.
* 설정에 **Asynchronous Input** 이 있습니다. 프레임 동기 방식과 맞지 않으면 이 옵션을 끄고 녹화/재생해 보세요. (직접 검증하지는 못했습니다)

### 오토플레이 모드 (녹화 없이 레벨 파일로 자동 연주)
녹화한 입력 대신 **.adofai 레벨 파일**을 읽어 "언제 키를 눌러야 하는지"를 계산하고 그대로 입력합니다. 기존 구조(전역 키 후킹 → 컨트롤러 → 플레이어 → SendInput)는 그대로이고, 플레이어 자리에 `AutoPlayer` 가 추가된 형태입니다.

1. `F6` 으로 오토플레이 모드 전환 (상태창의 "모드"에서 확인)
2. `L` 로 연주할 `.adofai` 파일 선택 (또는 `adofai_auto.ini` 의 `LevelPath`)
3. 게임에서 해당 레벨의 시작 화면을 띄우고 `E` → 시작 키가 곧 레벨 시작 입력이 되고, 계산된 시각표대로 키를 누릅니다. 재생 중 `E` 로 중단
4. 판정이 일정하게 빠르거나 늦으면 `F1`/`F2` 로 ±5ms 보정, 스피드 트라이얼이면 `F7`/`F8` 로 속도 배율 맞추기

계산 규칙: 1박 = 180° 회전, 시간 = 각도/180 × 60/BPM. `SetSpeed`(BPM/배율), `Twirl`(방향 반전), `Pause`, 레벨의 `pitch`, 시작 전 카운트다운(`countdownTicks`)을 반영합니다.

**제한 사항 (정직하게)**
* 미드스핀(999), 홀드 타일, 3개 이상 행성 레벨은 아직 지원하지 않고, 불러올 때 이유를 알려 줍니다.
* 카운트다운 길이와 게임의 입력 오프셋은 환경마다 다르므로, 처음에는 보정(`F1`/`F2`)으로 맞춰야 할 수 있습니다. 시간 계산은 손계산 기준 테스트로만 검증했고 실제 게임과의 동기는 직접 확인이 필요합니다.
* 게임 안에는 원래 자동 플레이(Otto)가 있고, 모드 방식(Unity Mod Manager/BepInEx + Harmony)으로 `RDC.auto` 를 켜는 도구들도 있습니다. 이 모드는 게임에 아무것도 주입하지 않는 **외부 입력 방식**입니다.
* 혼자 즐기는 용도로만 사용하고, 랭킹/대회 기록 제출에는 쓰지 마세요.

### 강화된 기능
* 재생 정확도: 목표 프레임을 **절대값**으로 계산(오차 누적 없음) + 목표 직전 바쁜 대기로 프레임이 바뀌는 즉시 입력
* 입력 방식: SendInput(가상 키 + 스캔 코드). 재생 키는 `adofai_auto.ini` 의 `PlayKey` 로 변경
* 프레임이 3초 이상 멈추면(게임 종료/정지) 재생 자동 중단
* 녹화 파일 관리: `Records/` 폴더에 시각 이름으로 보관, 파일 전환, 프레임 오프셋 보정

### 사용법<br/>
|단축키|설명|
|:---:|:---:|
R | 키보드 입력 녹화 시작/종료 (R 자체가 레벨 시작 입력이 됩니다)
E | 저장된 녹화 데이터로 오토플레이 / 재생 중 다시 누르면 중단
Q | 현재 녹화를 `Records/시각.apmd` 로 저장
W | 선택된 파일 불러오기 (없으면 가장 최근 파일)
F3 / F4 | 이전 / 다음 파일 불러오기
F1 / F2 | 전체 프레임 오프셋 -1 / +1 (모든 타일 간격에 적용)
F5 | 프레임 카운터 재탐색
F6 | 모드 전환 (녹화/재생 ↔ 오토플레이)
L | (오토플레이) .adofai 레벨 선택
F7 / F8 | (오토플레이) 속도 배율 -0.1 / +0.1
F1 / F2 | (오토플레이 모드에서는) 타이밍 보정 -5 / +5ms
Delete | 녹화 비우기

### 빌드 (GitHub Actions)
`.github/workflows/build.yml` 이 push / PR 때 Windows에서 Release/x64 로 빌드해 `ADOFAI_Auto.zip` 아티팩트로 올리고, `v1.0.0` 같은 태그를 push 하면 릴리스에도 첨부합니다.

### 설정 (`adofai_auto.ini`, 첫 실행 시 자동 생성)
`ProcessName`, `WindowTitleHint`, `PlayKey`, 오토플레이용 `LevelPath` / `SpeedMultiplier` / `AutoOffsetMs`, 그리고 선택 사항인 `FramePointer` / `PausePointer` / `InputOffsetPointer`
(형식 `모듈+오프셋:체인`, 예: `UnityPlayer.dll+0x017EEDD0:0x3D8,0x0,0x578,0xE30`)
